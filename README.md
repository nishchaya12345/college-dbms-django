# College DBMS – Django + MongoDB

A working DBMS demonstration built with **Django, MongoEngine, and MongoDB**. It demonstrates:

- CRUD for students and courses
- Student-course enrollments with referential checks
- Temporal student history through MongoEngine signals (trigger equivalent)
- Aggregation-pipeline stored-procedure equivalents
- A native MongoDB `student_summary` view
- MongoDB indexes
- JSON API endpoints and a browser-based UI

## Important ID design

`student_id`, `course_id`, `enrollment_id`, and `history_id` are normal MongoDB fields generated by MongoEngine `SequenceField`. They are **not** the MongoDB `_id` field. This is intentional because joins and lookups use these academic IDs.

## Requirements

- Python 3.10+
- MongoDB Community Server running locally, or another MongoDB server
- `pip`

## Setup on Windows PowerShell

```powershell
cd college_dbms_django
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, run the project with `.venv\Scripts\python.exe` directly.

Make sure MongoDB is running on `mongodb://localhost:27017`.

Optional environment variables:

```powershell
$env:MONGO_URI="mongodb://localhost:27017"
$env:MONGO_DB_NAME="college_dbms"
```

## Prepare the demonstration database

The included command clears the four demo collections and inserts a complete dataset:

```powershell
python manage.py run_demo
```

**Run this once after installing the fixed version.** It also removes old documents created by the previous schema where `student_id` was incorrectly stored as MongoDB `_id`.

## Start the website

```powershell
python manage.py migrate
python manage.py runserver
```

Open `http://127.0.0.1:8000/`.

### Main pages

- `/` – dashboard
- `/students/` – student CRUD and history
- `/courses/` – courses
- `/enrollments/` – student-course enrollment
- `/procedures/` – average GPA and student-detail aggregation procedures
- `/views/` – native MongoDB `student_summary` view
- `/indexes/` – collection indexes

## JSON API

- `GET/POST /api/students/`
- `GET/PUT/DELETE /api/students/<id>/`
- `GET /api/students/<id>/history/`
- `GET /api/courses/`
- `GET /api/procedures/student-details/<id>/`
- `GET /api/procedures/average-gpa/`
- `GET /api/views/student-summary/`
- `GET /api/indexes/<collection>/`

## Expected demo flow

1. Run `python manage.py run_demo`.
2. Start Django with `python manage.py runserver`.
3. Open **Students** and confirm IDs are displayed.
4. Edit a student and open **History** to see INSERT/UPDATE versions.
5. Open **Enrollments** and add another student-course relationship.
6. Open **Procedures**, enter a displayed student ID, and click **Look up**. The student appears even if they have no enrollment, and enrolled courses appear when present.
7. Open **Views** to see `student_summary` and total courses.
8. Open **Indexes** to verify indexes.
9. Delete a student and verify their enrollments are cascaded and the deletion is recorded in history.

## Notes

MongoDB does not provide SQL `CREATE PROCEDURE` or MySQL-style row triggers. The project demonstrates the closest practical equivalents: aggregation pipelines exposed through Python service functions and MongoEngine signals for automatic history/cascade behavior.
